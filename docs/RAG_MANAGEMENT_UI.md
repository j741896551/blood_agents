# Gradio RAG 知识库管理页

> 本页对应 2026-11-09 的本地集成页面。GitHub `dev` 此次只发布图册和说明，页面代码仍在本地集成。

## 打开页面

从项目虚拟环境启动 Gradio：

```bash
GRADIO_SERVER_PORT=7861 .venv312/bin/python -m blood_agents.web
```

页面左侧有“聊天对话”和“RAG 知识库”两个一级菜单。聊天页仍保留原来的会话列表、历史切换、确认按钮和调试信息；知识库管理使用独立的本地资料工作区。

知识库按流程分为四个页签。

| 页签 | 用途 |
| --- | --- |
| 01 资料管理 | 上传文件、填写来源信息、查看资料列表 |
| 02 清洗确认 | 对照原文，编辑并确认清洗稿，或删除未发布副本 |
| 03 切分与测试 | 选择已确认正文，调整参数，查看片段、原文及召回结果 |
| 04 发布与验证 | 确认评测、发布或撤回、检索正式索引 |

资料选择位于各自页签。切分页在选择已确认资料后开放测试入口。片段预览的正文与字符数只统计实际切出的正文，来源页码和章节路径另列。

切分设置区会就地显示资料状态和应用结果。已发布资料可以测试已保存的片段。修改正文或切分参数时，在“04 发布与验证”撤回后再编辑、测试、确认并重新发布。

## 上传与发布

1. 在“01 资料管理”上传 PDF、Markdown 或 UTF-8 TXT，填写标题和发布日期。来源链接、审核备注/适用范围为选填，内部文档或客服知识无需编造网址；填写链接时仍要求 HTTPS。
2. 点击“上传并查看清洗建议”。在“02 清洗确认”比对原始提取内容与清洗建议，可以自行编辑。建议移除项目提取工具生成的审核包装、Markdown 注释和可识别的印刷页码，保留物理页标题。确认正文后才生成片段。旧未发布草稿也可在此核对。
3. 在“03 切分与测试”选择资料，调整策略、字符上限与重叠，点击“应用参数并重新预览”。在“查看原文”展开原始提取文本或下载文件。新上传会保存原件，旧资料可下载原始提取文本。扫描 PDF 目前没有 OCR。
4. 在右侧“单题测试”输入问题并点击“测试当前资料”，直接查询所选资料当前配置的片段。该入口只用本地 BGE 临时向量，返回排名、召回分数、页码、章节和正文；不会写入 Milvus 或让草稿参与聊天。单题测试也可以满足发布前的测试步骤，结果合格仍需人工确认。
5. 在“策略对比”输入同一组问题和可选核验词。例如问题填“多少岁可以献血”，核验词填“十八,五十五”。页面比较片段数、正文长度和跨页片段数，并区分 Top-4 召回的核验词是否齐全、是否在同一片段齐全。核验词只统计当前资料的召回内容，用于辅助人工检查。
6. 检查候选后，打开“04 发布与验证”，依次点击“1. 确认评测合格”“2. 构建并发布索引”。正文或切分参数有变更时重新测试。发布按当前 `VECTOR_BACKEND` 建立/刷新检索器。
7. 在同页右侧“已发布知识库验证（发布后）”检查正式索引的召回片段和来源。此处不查询草稿；未发布任何文档时显示明确的空库提示。这里只有检索，没有回复模型调用，命中不代表最终答案正确。
8. 如发现问题，展开同页左侧“撤回资料”，点击“撤回发布”。资料文件和审核记录保留，但该资料会从当前活动 FAQ 检索器移除。
9. 删除未发布资料时，在“02 清洗确认”选择资料，展开“删除未发布资料”，勾选确认后点击“删除所选草稿”。删除范围是工作区清单和其中的文件副本。

### 用完整 PDF 演示

可直接上传《血站技术操作规程（2026版）》完整文本 PDF，项目限制为单文件 20 MiB、提取正文 200 万字符。2026-11-09 在隔离工作区验证了该文件的提取、清洗和切分。全文 218 页，物理第 72、172 页有待核对的 `�`。正文上限 500 字、重叠 80 字时，章节与段落策略切出 377 个片段，固定滑动窗口切出 290 个。这些数字来自切分预览，发布后的召回需要在正式索引里验证。 [公开通知及 PDF 附件](https://wsjk.ln.gov.cn/wsjk/zfxxgk/zc/gjjwj/2026070215022620516/index.shtml)

## 切分策略

- **章节与段落**：沿用标题和自然段边界。冒号引导句后的编号列表作为一个逻辑单元，识别相邻页开头的续列，片段保留页码范围。超长单元用滑窗。
- **段落合并**：合并连续自然段、短条文或完整列表至字符上限，可跨页，保持原文顺序。
- **固定滑动窗口**：将抽取并整理后的全文按固定字符窗口和重叠切分，可在条款或句子中截断。页码按窗口实际覆盖的正文计算。
- **语义分段**：恢复 PDF 段内折行，把完整句子、连同引导句的列表作为比较单位，用本地 `BAAI/bge-large-zh-v1.5` 比较相邻单位的相似度。相似度低于阈值或即将超出正文上限时断开。新片段从前一片段带入最多设定值的同章节正文，重叠计入正文上限。过长的单个单位由滑窗切分。

已有资料重新应用草稿参数后使用新版切分，重新测试和确认后可以发布。已发布资料在重新应用并发布前使用其原评测版本。

字符长度不是模型 Token 数。切分预览保留 PDF 页和章节位置；当前 PDF 表格解析能力有限，扫描件仍需 OCR 后续实现。

草稿从未参与 FAQ 查询。全新启动时没有预置知识，FAQ 必须在检索到已发布资料后才能据证回答。若解析、模型权重加载或索引重建失败，发布动作回退为草稿，当前聊天检索器保持原版本。现有知识清单 `corpus.json` 不会被网页改写。策略对比的临时向量只存在于本次回调内存；正式向量写入只发生在评测确认后的发布阶段。

## 来源、版本和冲突

- 标题用于清单和引用展示；来源链接是可选的追溯信息，不是正文能否作为证据的条件。有链接时只校验 HTTPS 格式，不会自动抓取或核实正文。无链接资料保留空值，标记为 `source_kind=uploaded`，不会生成假 URL 或自动标记为官方/公开规则；片段 ID 在内部追溯，不展示为来源。资料预览省略空来源；正式检索本次候选全部无链接时隐藏来源列，混合结果只保留实际提供的链接。回复提示词要求无链接时不输出来源栏目、空链接或内部路径。
- “审核备注 / 适用范围”是选填的人工说明，例如“客服手册 v2，仅适用深圳网点”“2026 版，已替代内部旧操作说明”。该文字会保存到清单，并随片段的 `provenance` 传给证据核验和回复模型，辅助理解引用范围。它不是自动审核结论，不会替代正文提供知识事实，也不实现按地区/版本/有效期的硬过滤或访问权限控制；仍要完成召回测试并人工确认后才能发布。
- 发布日期由上传者提供，核对日期用于记录入库时点；当前检索不会自动按生效日期筛选，上传日期也不能证明文件现行有效。
- 当前运行时没有内置知识语料；只有上传、切分、召回评测并确认合格后发布的资料才进入活动检索器。所有已发布片段做全局排序；Top-K 可能包含多份文件，但不保证每份文件都分到名额。
- 当前没有“新文件自动覆盖旧文件”的规则，也没有正式的有效期、适用地区、权威等级或替代关系筛选。上传时间较新不代表文件更有效。若资料冲突，不能据此宣称系统已自动解决；需要人工核实版本/适用范围，并在后续增加显式替代关系和冲突审查。
- 相关领域的文件可同时保持有效并共同被检索。若一个问题需要多个文件，Top-K 可能返回多个来源；是否召回齐全仍要用有标准答案片段的问题集验证。

## 文件和索引

- 上传正文、工作区清单和运行文件位于 `.local/rag/`，由 `.gitignore` 排除，不随 Agent 源码提交。可用 `BLOOD_AGENT_RAG_WORKSPACE` 指定其他本地目录；不要放入真实用户业务数据。
- 仅支持单文件不超过 20 MB，正文最多 200 万字符；日期用 `YYYY-MM-DD`。PDF 使用 `pypdf` 文本抽取，所需依赖为 `.[rag_ingest]`。
- 空库启动时不会连接或创建 Milvus collection，也不会载入 BGE；问题没有检索证据时 FAQ 拒答。`VECTOR_BACKEND=memory` 只做关键词检索；`faiss` 在进程内建立向量索引；`milvus` 按已发布资料/模型指纹复用或创建 collection。请以本机 `.env` 的后端设置判断是否持久化 embedding。
- 撤回或替换资料不会自动删除 Milvus 的旧 collection；它不会继续被当前检索器引用，但旧索引的物理清理仍需维护者按现有索引策略处理。
- 工作区是本机单进程演示功能，没有账号认证、权限角色、审计工作流、跨进程锁或后台任务队列。服务应保持绑定 `127.0.0.1`；不要将此页面直接暴露到公网或作为多人 SaaS 管理后台使用。
- 文件上传不会自动联网抓取来源网页。操作者需人工核对抽取内容、版本和适用范围。扫描件 OCR、网页抓取、复杂表格解析与版本差异比较仍待实现。

相关代码：`blood_agents/knowledge/workspace.py` 管理草稿、评测门禁和发布状态，`blood_agents/knowledge/ingest.py` 处理 PDF，`blood_agents/knowledge/rag.py` 提供共用切分器和可热更新的检索器，`blood_agents/web.py` 构建双一级菜单的 Gradio 工作台。

## 运行日志排查

- **`tuples format ... deprecated`**：旧版页面使用成对聊天消息，Gradio 在更新聊天区高度时重建组件，所以会反复警告。当前已改用 `type="messages"`，包括欢迎语、流式回复和历史恢复；不要只把这个警告过滤掉。旧服务需要重启，旧浏览器页面也需刷新。
- **刚点“应用参数”，测试仍说参数已改变**：先看按钮下方的应用结果。旧版把已发布资料不可修改的错误放在页面顶部，应用实际失败后测试便报参数不一致；新版会在切分区显示状态并锁定已发布资料的参数。先撤回为草稿，再应用新参数；若是草稿，模型加载等应用失败也会在按钮下方显示，需处理成功后再测试。
- **`GOAWAY / ENHANCE_YOUR_CALM / too_many_pings`**：这是 Milvus gRPC 连接的保活心跳触发服务端限制，并非大模型回复风控或 API 调用次数超限。当前 PyMilvus 2.6.17 默认 10 秒发一次心跳且空闲也发，而 Milvus Lite 3.2.2 没有相应放宽服务端策略。项目连接现在显式设置 `RAG_MILVUS_KEEPALIVE_SECONDS=300`（秒），空闲不发心跳，心跳响应等待 20 秒；该等待时间不是检索超时或大模型超时。配置在新建连接时生效，需要重启 Agent/Gradio。远端 Milvus 如有更严格策略，应与服务端协调间隔。不会通过关闭日志或放宽服务端防护掩盖连接问题。
- `grpc_options` 需要支持该参数的 SDK；项目将 `rag` 依赖最低版本提高至本机已验证的 PyMilvus 2.6.17，现有版本符合要求时不必重新安装。其他环境可执行 `.venv312/bin/python -m pip install -e '.[rag]'` 更新可选依赖。此变更不会清空 collection 或重建已有向量。

机制参考：[Gradio 角色消息格式](https://www.gradio.app/docs/gradio/chatbot)、[gRPC 保活说明](https://grpc.io/docs/guides/keepalive/)、[PyMilvus grpc_options 说明](https://github.com/milvus-io/pymilvus/pull/3258)。
