# 编排展示：当前演示步骤与历史验证

本页的操作说明按 2026-10-23 的 Python 3.12 / Gradio 5.50 代码校对；末尾旧日期的验证记录仅说明**当时版本**，不能代替当前页面或真实模型复验。业务数据来自本地 Mock/SQLite，不连接公司旧系统。当前内容风控模型暂停，默认透传；身份脱敏、写操作确认与工具回执边界仍有效。

## 启动编排诊断（无模型）

```bash
.venv312/bin/python -m pip install -e '.[dev,api,ui,mcp]'
env OPENAI_API_KEY= BACKUP_OPENAI_API_KEY= BLOOD_AGENT_MCP_REWARDS= \
  GRADIO_SERVER_PORT=7862 BLOOD_AGENT_DB=/private/tmp/blood-agent-demo-20261021.db \
  .venv312/bin/python -m blood_agents.web
```

访问 `http://127.0.0.1:7862/`。显式空 Key 阻止本地 `.env` 启用真实模型，MCP 开关也显式关闭；独立数据库及其自动创建的 checkpoint 文件避免修改日常演示库。端口占用时换一个空闲端口。**该路径会复用同名数据库，不会自动清空旧预约或会话**；需要隔离新的一次演示时换一个新的文件名，不要删除已有数据。无模型时只可检查编排、状态和工具轨迹：一般业务问答显示服务不可用，**唯一命中的静态演示说明仍可直接答复**。预约/取消/签到的待确认预览若未由回复模型成功生成并通过服务端校验，会变成 `preview_unavailable` 并撤销可执行确认状态；此时紧接着发送“确认预约/确认取消/确认签到”不能写入。自然业务对话需配置可用主/备模型后重启；当前项目不代为测试外部 Key。

页面默认演示用户为 `U1001`，左侧显示该用户最近的已保存会话，进入时默认打开最新一条；若没有记录，或点击左侧“新对话”/聊天框清空图标，会出现固定的能力欢迎引导。欢迎引导仅在页面显示，不进入 LangGraph、对话数据库或标题摘要。用户 ID 输入框只是本地演示身份，**没有登录认证**；切换用户后列表按所填 ID 重新加载。选择旧会话会只读回显最近 100 轮脱敏历史，下一条新消息才用同一 `session_id` 的 checkpoint 续接。旧会话和业务数据不会因“新对话”而删除。

## 当前版真实模型自测与证据回传（由用户执行）

本项仍**待验收**。请先确认 `.env` 中配置的是你愿意自行调用的模型平台；不要在聊天、截图或回传日志中附上 API Key。每次选择一个**新的**合成 Mock 数据库文件名，避免已有预约影响结果；下面只是启动示例，端口占用时可换端口，文件名已存在时应换新名字而不是清空旧库：

```bash
BLOOD_AGENT_DB=/private/tmp/blood-agent-model-check-20261022-01.db \
BLOOD_AGENT_TRACE_MODE=full \
BLOOD_AGENT_TRACE_FILE=./logs/blood-agent-model-check.jsonl \
GRADIO_SERVER_PORT=7862 .venv312/bin/python -m blood_agents.web
```

使用页面中的演示用户 `U1001`，点击“新对话”。页面自动欢迎语是固定展示内容，**不算模型回复**。本次只检查一条正向预约链路；全部使用合成身份资料，不输入真实姓名、证件、电话或地址：

1. 发“我要预约”，从页面实际返回的可预约项中选定**完整日期、网点和时段**，按提示确认本次献血人。首轮原始编排数据应显示 `model_info.mode=llm` 与 `response_info.mode=llm`，不能把规则降级算作模型理解通过；聊天正文出现后，侧栏应再更新为有意义的会话标题。若仍为“待生成标题”，记录为标题/摘要未通过，但不要因此把业务回复算作失败。
2. 在点击或发送最终“确认预约”**之前**，先看聊天框确实显示了完整的待确认预约信息。折叠的原始编排数据应有 `response_info.mode=llm`、`result.status=awaiting_confirmation`、`slots.preview_delivered=true`，且 `tool_trace` **没有** `submit_appointment`。`preview_delivered` 只是服务端可确认标记，还须人工核对浏览器确实展示了预览。
3. 明确回复“确认预约”后，核对本轮 `tool_trace` 恰有一次 `submit_appointment`，并核对 `result` 的 Mock 接口回执。只有回执成功才算预约成功；若接口拒绝，应检查模型是否据实说明原因，不能把失败写成成功。
4. 再问“查询我的预约记录”，应只读调用 `query_user_appointments`，查到与提交回执相同的预约号；本轮不应再次出现 `submit_appointment`。若未成功提交，不以模型文字或旧历史偏好充当已提交记录。

每轮保留页面里的 `session_id` 和 `trace_id`，以及“本轮执行摘要/原始编排数据”中的 `model_info`、`response_info`、`result.status`、`slots.preview_delivered`（预览轮）、`tool_trace`。标题与摘要另核对侧栏标题及同一首轮 trace 下的 `conversation.digest.saved`；标题失败不应重放预约写入。可用 `python -m blood_agents.log.trace_viewer --trace-id '某轮trace_id'` 查看该轮时间线。`full` 日志含用户原话及完整模型输入/输出，只适合本地合成数据排查；回传前请检查并脱敏，不要直接上传整个 JSONL、密钥或真实个人资料。若任一检查失败，提供**失败的单轮 trace ID、页面可见答复与相关脱敏字段**即可定位；未拿到这些当前版证据前，不把历史模型页面记录写作本次通过。此流程不测试真实备用供应商的容灾质量。

### 保守流式回复自测

在**没有活动预约或兑换流程的新会话**中，发一个非问候、非献血业务的普通聊天问题，例如“今天心情不错，想随便聊聊”。先在原始编排数据核对本轮为 `intent=general`、`result.status=general`；若模型分流到其他领域，该轮不用于判断普通导航流式是否生效。普通导航回复应逐步增加文本，完成后以最终通过校验的整段答复为准；“你好”或“你能做什么”需检查分组列表格式，因此仍整段显示。另分别问一个预约问题和一个献血知识问题，确认页面只在完整回复后显示正文，不将待确认预览或 FAQ 的未校验片段提前展示。

按该轮 `trace_id` 查看 `model.stream.first_chunk` 的 `first_chunk_ms`，以及 `model.attempt.finished` / `model.response` 的 `chunk_count`、`output_chars` 和首片耗时，并与实际页面观察分开记录。流式中断或最终校验失败会以服务不可用答复覆盖页面草稿，但已被看到或复制的片段无法真正撤回；关闭页面也不保证同步供应商 SDK 立刻取消底层请求或费用。本地 2026-10-23 的隔离假回复页面已验证分段/整段显示机制，**尚未验证真实模型流速、取消行为或内容风控效果**；当前内容风控模型仍暂停。

## 主导航问候

新对话已自动显示欢迎引导，**不必先发送“你好”才能看到能力列表**。若要专门验证主导航，可再发送“你好”：缓存检查不命中，`node_trace` 从 `supervisor → main_agent_response → general_reply` 开始，意图为 `general`，业务工具 0 次；无模型时回复为服务不可用，`response_info.mode=unavailable`。缓存未命中的检查只记 `cache.lookup` 追踪事件，不加入既有 `node_trace`；命中时才以单独的 `static_faq_cache` 节点结束本轮。已有预约进行中再次问候时，预约参数仍保留，之后可继续补充日期和网点。有模型时 `general_reply` 调用回复模型。

另开**无活动预约/兑换**的新会话，问“这是演示数据吗？”：在条目有效且唯一命中时，`node_trace` 只有 `static_faq_cache`，`response_info.mode=static_cache`，不调用模型或业务工具，纯缓存会话的侧栏标题也不用模型。问“这是演示数据吗？顺便查询积分”不会命中；过期、重复匹配或活动业务流程也回到原图。当前页面“本轮执行摘要”的模式名称未专门显示 `static_cache`，请以折叠区的原始 `response_info` 和节点轨迹为准。缓存文案只涉及演示系统范围，不缓存个人积分、预约名额或医疗结论。

## 成功流程

用户 ID 为 `U1001`，保持会话 ID 不变，并确保已配置可用的回复模型、待确认预览确实出现在聊天框中；无模型的诊断页面不能走完写操作：

当前 `preview_delivered` 是**服务端**根据回复模型成功生成并通过校验所设的可确认标记；它不是浏览器回执。网络在图完成后断开等“服务端成功、用户实际未看见”的情形尚无客户端确认机制，不能将此标记解释为生产级送达证明。

1. 发送“我要预约”。缓存不命中，摘要从 `supervisor → appointment_subgraph → appointment_understand → appointment_tool_plan → appointment_agent → appointment_reply → appointment_handoff` 开始，通常为 `need_more_info` 并等待用户；会查询用户资料、网点与历史，无提交。配置模型时，可在摘要看到只读工具规划，候选时段可由模型排版；内容风控当前为透传，不能把它当作已完成内容安全审核。
2. 发送“还是上次网点，选择明天上午”。摘要显示 `awaiting_confirmation`、已选日期/网点/时段，仍无提交。日期基于服务启动当日的 Mock 配置；长期运行跨日后应重启演示服务或直接选页面返回的日期。
3. 查看当前轮 Mock 资料中的历史献血人；若预览询问是否仍由该人献血，可回复“是”确认献血人，此时 SQLite 仍没有新预约。也可说“不是我献血，是帮朋友预约”，随后只提供**合成**资料“献血人姓名：张三，手机号：13912345678，身份证号：310101199303031234，性别：男，A型血，全血300cc”，再核对掩码预览。可选：发送“查询我的积分”，预约状态会保留。不要输入真实个人证件资料。
4. 发送“确认预约”。预约子图在本轮调用 `submit_appointment` 并等待 Mock 返回，摘要显示成功或失败的真实接口结果；写入只执行一次。成功预约号来自 Mock 接口；若同一献血人当天已有预约，接口返回 `ALREADY_BOOKED`，模型应转述失败原因。无模型时只显示服务不可用，可再查询真实结果，避免盲目重复提交。
5. 发送“帮我查询一下我的预约信息”。摘要显示 `appointments_found`，本轮只有只读 `query_user_appointments` 工具；回复中的预约号与第 4 步相同，不再调用 `submit_appointment`。即使新建聊天会话，只要 `user_id` 与 Mock 数据库相同，也能查询到这笔已提交预约。首次试用时用于推荐“上次网点”的预置历史偏好，不等于已提交预约查询结果。
6. 点击“新对话”（或聊天框清空图标）。当前显示切到带欢迎引导的新会话，ID 更新；旧聊天、标题、checkpoint 和数据库预约均保留，可从左侧最近对话返回。

## 失败及取消

- 将用户 ID 改为 `UNKNOWN`，发送“我要预约”。Mock 返回 `USER_NOT_FOUND`；摘要标记预约节点与资料工具失败，无提交。
- 改回 `U1001`，重新收集参数，发送“退出预约”或“我不想预约了”。本轮无业务工具，清空预约槽位，并由 `main_agent_return` 接收取消结果。之后“确认预约”不能提交已取消的旧预览。
- 对已提交的 `U1001` 预约，说“取消明天下午市中心献血屋的预约”。首轮应仅查询并返回 `awaiting_action_confirmation`；明确回复“确认取消”后才出现 `cancel_appointment` 工具与 `cancelled` 回执。说“确认预约”不能代替“确认取消”。
- 用 `U1002` 查询 Mock 预置的已预约、已取消、已签到、已献血四状态；对唯一的后天上午大学城献血车已预约记录说“签到后天上午大学城献血车的预约”，再回复“确认签到”才调用 `checkin_appointment`。已签到或已献血记录再取消应被 Mock 拒绝。
- 选择页面不存在的时段/网点，显示 `slot_unavailable`，不得产生提交工具。
- 提交接口拒绝、模型备用切换与全失败可通过自动化故障注入复现，不在正常网页伪造失败，也不引入真实生产接口。

## 理解摘要

摘要是本轮结束后依据真实 `node_trace`、`tool_trace`、`model_info` 与 `response_info` 生成的纯文本，不是实时节点进度。只展示白名单业务参数，不展示实名资料/完整响应。原始 JSON 保留在折叠区域中，包含更完整的本地演示数据，不应直接作为生产公开审计界面。

理解模式的 `rules` 表示未启用模型，`llm` 表示模型理解，`rules_fallback` 表示模型失败后规则降级；缓存命中时内部 `model_info.mode=skipped_static_cache`。回复模式可为 `llm`、`static_cache` 或 `unavailable`；`risk_refusal` 只可能出现在显式启用内容风控的相应路径，当前默认透传。模型服务显示 primary/backup；工具规划和故障注入见 `tests/test_tool_planner_risk.py`。当前 UI 的简短摘要尚未给静态缓存模式设置中文别名，原始编排 JSON 是该模式的准确来源。下方离线/浏览器记录为改动前的历史验证，不代表当前版本完整多轮已复验。
